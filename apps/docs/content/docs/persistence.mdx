A [Session](/docs/concepts#session) is live and process-bound. A [Transcript](/docs/concepts#transcript) is the durable, serializable record of its committed Messages. Persistence is always explicit: without a `transcripts` store, Mitome writes nothing to disk.

```ts
import { defineMitome, fileTranscripts } from "@mitome/sdk";

export default defineMitome({
  agent,
  transcripts: fileTranscripts(),
});
```

Two stores ship with the SDK:

- `fileTranscripts(directory?)` writes to `<config-dir>/transcripts` by default, or to the directory you pass. With no argument and no resolvable config directory it throws immediately; set `MITOME_HOME` or pass a path. See [Configuration](/docs/configuration).
- `memoryTranscripts()` keeps Transcripts in memory for as long as the returned value lives. Use it in tests or when several Sessions in one process should share Transcripts without disk writes.

In a Mitome Definition, the declared store is handed to every Host, so one-shot runs and the TUI resume from the same place. Hosts never discover or construct a store on their own.

## Embed and resume

Pass the same store to `withSession`. Every resume creates an independent child Transcript whose `parentTranscriptId` points at the seed:

```ts
import { defineAgent, memoryTranscripts, withSession } from "@mitome/sdk";
import { openai } from "@mitome/providers/openai";

const agent = defineAgent({
  providers: [openai()],
  model: "openai/gpt-5.4-mini",
});
const transcripts = memoryTranscripts();

const parentId = await withSession(agent, { transcripts }, async (session) => {
  await Array.fromAsync(session.runTurn("Remember that my project is blue."));
  return session.transcript().id;
});

await withSession(agent, { transcripts, resume: parentId }, async (session) => {
  for await (const event of session.runTurn("What color is my project?")) {
    if (event.type === "model-output") process.stdout.write(event.text);
  }
});
```

An unknown `resume` id rejects with `TranscriptNotFound`. You can also seed from a value you already hold: `withSession(agent, { transcript: session.transcript() }, ...)` needs no store at all.

## Commit boundary

Only a completed Turn updates its Transcript, and only after the store's `save` succeeds. Until then `session.history()` and `session.transcript()` still show the previous state. This means:

- A failed or interrupted Turn leaves the Transcript unchanged.
- A `StoreError` from `save` fails the Turn the same way. The Turn is absent from `history()` and `transcript()`; sending the Message again runs the Model and the turn-end Hooks again.
- Resuming never reattaches a live Session. Extension Resources are acquired again, a new Session and Transcript id are created, and any Approval pending in the old process is gone.

Each Turn event is also appended to the store as a versioned record through `appendEvent`. That event log is **write-only observability data**: it may end midway through an interrupted Turn and is never replayed to rebuild a Session. The Transcript snapshot is the sole resume mechanism.

## Listing Transcripts

`transcripts.list()` returns one `TranscriptSummary` per stored Transcript: id, parent id, timestamps, message count, and a one-line preview of the first user Message. The [TUI's picker](/docs/tui) is built on it.

## Other stores

Any object implementing the Promise-first `TranscriptStore` interface (`save`, `load`, `list`, `appendEvent`) works where the built-in stores do. Writing one for a database is covered under [Custom Transcript store](/docs/custom-transcript-store): return `null` from `load` for an unknown id, and treat stored bytes as untrusted input to validate before returning a Transcript.
