A [Provider](/docs/concepts#provider) is a configured integration through which an Agent reaches a family of [Models](/docs/concepts#model). You register Provider values in `defineAgent`, then name the Default Model with a **qualified Model id** in `provider/model` form.

```ts
import { defineAgent } from "@mitome/sdk";
import { openai } from "@mitome/providers/openai";

const agent = defineAgent({
  providers: [openai()],
  model: "openai/gpt-5.4-mini",
});
```

The prefix before the slash must be the id of a registered Provider; `openai()` has id `openai`. Provider ids must be unique within one Agent Definition, and the Provider package has no root import: import each Provider from its own path.

## Catalog, not entitlement

Every Provider ships a `knownModelIds` catalog. It drives editor completions for the `model` field and the choices `mitome init` offers. It is not a closed list: any id under a registered Provider is accepted, and the Provider decides at request time whether your account may use it. The [OpenAI-compatible Provider](/docs/providers/openai-compatible) has an empty catalog for exactly this reason.

The Default Model applies when a Turn does not name another; a Turn can select a different Model under any registered Provider, as shown under [Sessions](/docs/sessions#choose-a-model-per-turn).

## Available Providers

| Provider                                                        | Import path                           | Credential                    |
| --------------------------------------------------------------- | ------------------------------------- | ----------------------------- |
| [OpenAI](/docs/providers/openai)                                | `@mitome/providers/openai`            | API key in `OPENAI_API_KEY`   |
| [OpenAI-compatible endpoint](/docs/providers/openai-compatible) | `@mitome/providers/openai-compatible` | optional API key, you name it |
| [Codex subscription](/docs/providers/codex)                     | `@mitome/providers/openai-codex`      | ChatGPT OAuth in `auth.json`  |

Codex is not `openai()` with another `baseUrl`, and not an OpenAI-compatible endpoint either; its authentication and transport differ. Use the Codex Provider for it.

To build a Provider for another service, see [Provider authoring](/docs/provider-authoring).
