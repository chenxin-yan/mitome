The OpenAI Provider talks to the official OpenAI Responses API and authenticates with an API key. It is distinct from the [Codex subscription Provider](/docs/providers/codex), which uses a ChatGPT login instead.

```ts
import { defineAgent } from "@mitome/sdk";
import { openai } from "@mitome/providers/openai";

const agent = defineAgent({
  providers: [openai()],
  model: "openai/gpt-5.4-mini",
});
```

`openai()` reads the key from `OPENAI_API_KEY` when a Session first uses the Provider and fails if the variable is missing or empty.

## Options

| Option      | Default                     | Purpose                                                                                   |
| ----------- | --------------------------- | ----------------------------------------------------------------------------------------- |
| `apiKeyEnv` | `"OPENAI_API_KEY"`          | Name of the environment variable holding the key.                                         |
| `baseUrl`   | `https://api.openai.com/v1` | Responses API root, for proxies and controlled endpoints that still are OpenAI.           |
| `transport` | WebSocket on Bun and Node   | `"http"` or `"websocket"`. The default falls back to HTTP where WebSocket is unavailable. |

```ts
const provider = openai({ apiKeyEnv: "MY_OPENAI_KEY", transport: "http" });
```

The WebSocket transport reuses one connection across requests and closes it after a minute idle. A failed WebSocket request is not retried over HTTP, and an explicit `"websocket"` outside Bun or Node throws; pass `transport: "http"` for HTTP-only proxies.

If the endpoint is a different service that happens to speak the OpenAI protocol, give it its own identity with [`openaiCompatible()`](/docs/providers/openai-compatible) instead of overriding `baseUrl`.

## Provide the key

From a terminal, `mitome auth login` prompts for the variable named by `apiKeyEnv` with masked input and stores it in `<config-dir>/.env`. Embedded applications never read `.env`; set the variable in the process environment your platform provides.

```sh
mitome auth login
```

Where the file lives, its permissions, and the precedence rules are on the [Configuration](/docs/configuration#credentials) page. Never put a key in `index.ts`, commit `.env`, or let it reach the Agent as Instructions or Tool output.

## Model catalog

`knownModelIds` lists the Tool-capable OpenAI Models offered as completions and in `mitome init`. Any other Model id under `openai/` is accepted and checked by OpenAI at request time; see [Catalog, not entitlement](/docs/providers#catalog-not-entitlement).
