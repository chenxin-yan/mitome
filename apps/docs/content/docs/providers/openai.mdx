title: OpenAI providers

Mitome exposes separate factories because OpenAI's Responses API and the commonly implemented Chat Completions API are different protocols.

| Target                     | Package                     | Endpoint            |
| -------------------------- | --------------------------- | ------------------- |
| Official OpenAI            | `@mitome/openai`            | `/responses`        |
| OpenAI-compatible provider | `@mitome/openai-compatible` | `/chat/completions` |

## Official OpenAI

The CLI path is the shortest route:

```sh
mitome init
mitome
```

To change or rotate the saved API key later, run `mitome auth login`. The generated SDK Definition uses the public `openai()` and `env()` factories:

<include>../examples/quickstart.ts#definition</include>

`env("OPENAI_API_KEY")` only describes the variable; the provider reads `process.env.OPENAI_API_KEY` at Session startup. A missing or empty variable is a Session startup failure. Known Model IDs autocomplete, but arbitrary, private, future, and fine-tuned strings pass through unchanged; OpenAI remains the entitlement authority.

`openai` uses OpenAI's Responses API. Its optional `baseUrl` must expose that protocol; setting it does not switch the factory to Chat Completions.

<include>../examples/providers.ts#openai-baseurl</include>

### Use a process variable without the CLI

For an embedded SDK Session, set the variable in the launching process and use the same Definition:

```sh
export OPENAI_API_KEY='sk-...redacted...'
bun run agent.ts
```

Use a synthetic redacted form only in documentation. Do not commit a `.env`, copy an API key into a Definition, log it, or put it in a fixture. The CLI alone reads its config `.env`; embedded SDK Sessions use the process environment untouched. See [credential locations and precedence](/docs/security).

## OpenAI-compatible providers

<include>../examples/providers.ts#openai-compatible</include>

The `baseUrl` is required so a compatible Definition cannot accidentally target official OpenAI through the compatibility transport. Model identifiers pass through unchanged, and the provider remains responsible for accepting the model and supporting the Chat Completions streaming and Tool features the Definition uses.

Mitome does not detect providers from model names or URLs and does not retry one protocol with the other. Backend rejections surface as ordinary provider failures.

Credentials are read from the named environment variable when the Session starts. The CLI loads its configured `.env`; embedded SDK Sessions use the host process environment unchanged.

ChatGPT subscription access is separate from both API-key integrations and belongs to [`@mitome/openai-codex`](/docs/providers/codex).
