Mitome is developed at [github.com/chenxin-yan/mitome](https://github.com/chenxin-yan/mitome). Issues are the triage surface; open one before a large change. The [canonical library plan](https://github.com/chenxin-yan/mitome/blob/main/docs/plans/effect-native-library.md) records the accepted redesign and open proof gates; [#174](https://github.com/chenxin-yan/mitome/issues/174) remains its single delivery roadmap. The [MVP plan](https://github.com/chenxin-yan/mitome/blob/main/docs/plans/mvp-plan.md) records what the current packages implement.

## Repository layout

- `packages/mitome`, `packages/providers`, `packages/cli`, `packages/create-mitome`: one directory each, with tests under `test/`. These four, plus the platform packages under `packages/cli/npm/`, form the planned release cohort; none is published yet. The terminal is part of `packages/cli`.
- `packages/config`: the shared TypeScript configuration.
- `apps/docs`: this site (fumadocs on TanStack Start); pages live in `apps/docs/content/docs`.
- `docs/adr`: architecture decision records; `CONTEXT.md` at the root is the domain glossary every page and identifier follows. `docs/plans/effect-native-library.md` is the canonical redesign plan; `docs/research` is supporting evidence.
- `scripts`: a private workspace for repository tooling, release fixtures and their tests.
- `.changeset`: pending release notes.

## Toolchain

[mise](https://mise.jdx.dev) installs the pinned Node version from `.node-version`, the pnpm version from `packageManager` in `package.json`, and the Bun version from `mise.toml`. pnpm installs the workspace; [Vite+](https://viteplus.dev) (`vp`, run as `pnpm vp`) formats, lints, type-checks, runs the tests and runs the workspace's tasks; Bun runs the CLI, compiles its binary and runs the scripts that use its APIs. Then:

```sh
pnpm install
```

The install also sets up a commit hook that checks and fixes the staged files, and patches the `typescript` package's `tsc` with `effect-tsgo patch` so that an editor using the workspace TypeScript shows Effect's diagnostics. Tasks live in each package's `vite.config.ts`, with the shared ones in `vite.shared.ts`; `pnpm vp run <task>` runs one after the tasks it depends on, from cache when nothing it reads changed. The packages resolve each other from source through the private `@mitome/source` export condition, so an edit is seen everywhere without a build. `pnpm run build` builds the published libraries with `vp pack` and compiles the `mitome` command to `packages/cli/dist/local/mitome`, and `pnpm run dev:cli` runs it from source with `MITOME_HOME` set to the git-ignored `.dev-home` and `ANTHROPIC_CONFIG_DIR` to a directory inside it.

Narrower commands:

```sh
pnpm vp run --filter @mitome/core test   # one package's tests, from source
pnpm vp test run test/agent/agent.test.ts   # one test file, from its package directory
bun --bun vp test run test/command.test.ts  # the same in packages/cli, whose tests need the Bun runtime
```

## Gates

To match CI, run:

```sh
pnpm install --frozen-lockfile
pnpm vp run check
pnpm test
pnpm run build
pnpm run test:dist
```

`pnpm test` runs every package's tests from source and needs nothing built. `pnpm run test:dist` runs the tests of built output, tagged `dist` (`@module-tag dist` on a file, `tags: ["dist"]` on a test): a consumer's declarations, cross-process imports of `dist`, the compiled binary and its terminal, the scaffolded application and the release fixtures, each after the builds it needs. A file with such tests needs `pnpm run build` before `pnpm vp test run` runs it alone.

`pnpm vp run check` formats, lints and type-checks the whole repository with Effect's diagnostics, which it gets by running `vp check` through `effect-tsgo`; a bare `vp check` misses them. `pnpm run check:fix` applies format and lint fixes. `pnpm run build:docs` is the site-only build. It fails on an internal link to a page that does not exist and on an `<auto-type-table>` whose type cannot be resolved, so it is the documentation gate as well. Anchors within a page are not checked.

## Generated artifacts

Two hint modules are generated and git-ignored; do not edit them by hand: `packages/providers/src/openai/models.ts` and `packages/create-mitome/src/model-hints.ts`. The `hints:generate` task writes them, and the check and every build run it first. The snapshot and the Codex and Anthropic catalogs are committed inputs.

| Artifact                                                                            | Command                  | Source                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI Model catalog and the Model choices of `npm create mitome` and `mitome init` | `pnpm run hints:refresh` | [models.dev](https://models.dev); the snapshot is committed at `scripts/models-dev.snapshot.json` and `hints:generate` uses it offline.                                                                     |
| Codex and Anthropic Model catalogs                                                  | none                     | Hand-maintained in `packages/providers/src/openai-codex/models.ts` and `packages/providers/src/anthropic/models.ts`; `hints:generate` copies them into those choices. Update them when the services change. |

## Releasing

Every user-visible change adds a changeset: run `pnpm exec changeset`, or write the markdown file under `.changeset` by hand. The release cohort shares one version; the release workflow opens a version pull request from pending changesets and publishes the cohort together when it merges.

## Recording decisions

An architecture decision that changes a public contract or a cross-cutting rule gets an ADR in `docs/adr`, numbered sequentially, in the style of its neighbours: the decision in prose, then consequences. Mixed decisions retain meaningful guarantees with `status: amended by ADR-NNNN` and a successor link. For this prerelease redesign, fully obsolete decisions and Promise/Extension API guides are removed; Git history preserves them. Repair inbound links and navigation on deletion. Code samples in these pages must be copied from, or checked against, code that compiles in the repository, never proposed signatures. Terms go in the glossary-only `CONTEXT.md`; use the term it defines and none of the ones it says to avoid.

## Manual terminal check

Automated tests drive the terminal through OpenTUI's test renderer and the compiled `mitome` through a pseudo-terminal on Linux. Before a release, also run `mitome --config <directory>` in a real terminal on each supported platform and confirm: Enter inserts a newline and Alt-Enter sends; repeated submissions reuse one Session; a pending Approval is decided only after Tab, with `y` or `n`; Esc interrupts and the next submission succeeds; Ctrl-C exits and restores the terminal.

## Issue labels

`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, and `wontfix` are the labels in use; a new issue starts at `needs-triage`.
