Effect-native Host and Provider authoring surface. Application code should prefer `@mitome/sdk`
or `@mitome/sdk/effect`; Core carries a weaker stability guarantee.

## Classes

### AgentDefinitionError

The Agent Definition cannot compile: duplicate Provider ids, a malformed or unregistered Default
Model, conflicting Extension or Tool names, Tool handlers without a matching Tool, or malformed
`approvals` rules. `issues` lists every problem found, not just the first.

```ts
class AgentDefinitionError extends Error {
  readonly _tag: "AgentDefinitionError";
  /** Every problem found, at least one. */
  readonly issues: readonly [string, ...string[]];
  /** Every issue, one per line. */
  readonly message: string;
}
```

### ApprovalResolutionError

An Approval decision could not be applied: it was already resolved, or (`reason: "not-pending"`)
its Turn has ended. Decisions are one-shot.

```ts
class ApprovalResolutionError extends Error {
  readonly _tag: "ApprovalResolutionError";
  readonly reason?: "not-pending";
  /** Description derived from `reason`. */
  readonly message: string;
}
```

### SessionBusyError

Overlapping `Session.runTurn()` while a Turn is active.

```ts
class SessionBusyError extends Error {
  readonly _tag: "SessionBusyError";
  /** Fixed description; the error carries no fields. */
  readonly message: string;
}
```

### SessionReleasedError

Turn requested on a Session whose scope has already closed.

```ts
class SessionReleasedError extends Error {
  readonly _tag: "SessionReleasedError";
  /** Fixed description; the error carries no fields. */
  readonly message: string;
}
```

### StoreError

A Transcript store operation failed. From `save` or a mid-Turn `appendEvent`, the Turn fails
before commit. From the `appendEvent` of the final `response-complete` record, the Turn is already
committed and the failure surfaces to the consumer instead of `response-complete`.

```ts
class StoreError extends Error {
  readonly _tag: "StoreError";
  readonly message: string;
  readonly cause?: unknown;
}
```

### TranscriptNotFound

No Transcript exists for the requested id.

```ts
class TranscriptNotFound extends Error {
  readonly _tag: "TranscriptNotFound";
  readonly id: string;
}
```

### TurnError

A model, Tool, or Extension Hook failed while completing a Turn.

```ts
class TurnError extends Error {
  readonly _tag: "TurnError";
  readonly message: string;
  readonly cause: unknown;
}
```

### Routes

Effect-native Route store: maps an external conversation to its latest Transcript so the next
Message resumes where it left off. Every Session mints a fresh Transcript id and resume forks, so
a Channel advances the Route after each committed Turn. Channels receive the store through their
own factory options, not through
[`ChannelHostContext`](/docs/reference/api/core#channelhostcontext).

Ceiling: Transcript save and Route advance are two separate writes with no transaction across
them. A Channel must not report success to its surface before both have landed, and must
tolerate a stale pointer: a Route may name a Transcript that no longer loads, or lag one Turn
behind the store, in which case the Channel resumes from what it can load or starts fresh.

<auto-type-table path="../../../../../../packages/core/src/index.ts" name="Routes" />

## Type Aliases

### AnyExtension

```ts
type AnyExtension = Extension<any, unknown, any> | Extension<never, any, any>;
```

Any Extension regardless of its Resource. Layer's ROut is contravariant while hook/handler
Effects are covariant in R, so no single parameterization accepts every Extension; the union's
arms cover both variance directions.

### AnyProvider

```ts
type AnyProvider = Provider<string, ReadonlyArray<string>>;
```

Any configured Provider, for code that holds Providers without knowing their catalog.

### ApprovalPolicy

```ts
type ApprovalPolicy<Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>> =
  ApprovalRules<Extensions> | ApprovalPolicyCallback<Extensions>;
```

The Agent author's sparse Approval override: Tools it does not mention keep their author's
`needsApproval` default. `deny` and `ask` always hold; `allow` only bypasses the Tool default and
never an Extension veto or `"ask"`.

### ApprovalPolicyCall

```ts
type ApprovalPolicyCall<
  Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>,
> = [KnowsEveryToolName<Extensions>] extends [true]
  ? KnownToolCall<
      ContributionsOf<Extensions[number]>,
      KnownToolNames<ContributionsOf<Extensions[number]>>
    >
  : { readonly name: string; readonly params: unknown; readonly toolCallId: string };
```

The Tool call an `approvals` callback decides on; `params` is the decoded Tool input. When every
Extension's Tool names are known at the type level, comparing `name` narrows `params` to that
Tool's input; one Extension typed without contributions leaves `name: string` and
`params: unknown` for the whole call, since its Tools reach the callback too. `KnownToolCall`
distributes over the known names to a union of `{ name; params; toolCallId }` objects, one per
Tool.

### ApprovalPolicyCallback

```ts
type ApprovalPolicyCallback<
  Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>,
> = (call: ApprovalPolicyCall<Extensions>) => ApprovalPolicyDecision | undefined;
```

Synchronous, param-aware Approval rule. Throwing, returning a Promise or Effect, or returning
anything other than a decision or `undefined` fails the Turn before the Tool runs.

### ApprovalPolicyDecision

```ts
type ApprovalPolicyDecision = "allow" | "ask" | "deny";
```

The Agent author's opinion on one Tool call; `undefined` defers to the Tool's `needsApproval`.

### ApprovalRequirement

```ts
type ApprovalRequirement = "tool" | "policy" | "predicate-error";
```

Why a Tool call paused for Approval: the Tool author's `needsApproval` (`tool`), the Agent's
`approvals` or an Extension `preTool` `"ask"` (`policy`), or a `needsApproval` predicate that
failed and therefore fails closed (`predicate-error`).

[`AuthCapability`](/docs/reference/api/core#authcapability). The decoded type of
[`CredentialDescriptorSchema`](/docs/reference/api/core#credentialdescriptorschema).

### TurnEvent

```ts
type TurnEvent =
  | { readonly type: "model-output"; readonly text: string }
  | { readonly type: "reasoning"; readonly text: string }
  | {
      readonly type: "tool-call";
      readonly id: string;
      readonly name: string;
      readonly params: unknown;
    }
  | {
      readonly type: "tool-result";
      readonly id: string;
      readonly name: string;
      readonly result: unknown;
      readonly isFailure: boolean;
    }
  | {
      readonly type: "approval-required";
      readonly approvalId: string;
      readonly toolCallId: string;
      readonly name: string;
      readonly params: unknown;
      readonly requirement: ApprovalRequirement;
      /** Lets the Tool call run. One-shot: resolving again or after the Turn ended fails. */
      readonly approve: () => Effect.Effect<void, ApprovalResolutionError>;
      /** Rejects the Tool call; the Model sees `reason`. One-shot like `approve`. */
      readonly deny: (reason?: string) => Effect.Effect<void, ApprovalResolutionError>;
    }
  | {
      readonly type: "response-complete";
      readonly finishReason?: Response.FinishReason | undefined;
      readonly usage?: Response.Usage | undefined;
    };
```

One event emitted while a Turn runs. `approval-required` pauses the Turn until `approve` or
`deny` resolves; `response-complete` is the final event of a successful Turn and is emitted only
after the Transcript save succeeded.

### TurnEventDto

```ts
type TurnEventDto =
  | { readonly type: "model-output"; readonly text: string }
  | { readonly type: "reasoning"; readonly text: string }
  | {
      readonly type: "tool-call";
      readonly id: string;
      readonly name: string;
      readonly params: Json;
    }
  | {
      readonly type: "tool-result";
      readonly id: string;
      readonly name: string;
      readonly result: Json;
      readonly isFailure: boolean;
    }
  | {
      readonly type: "approval-required";
      readonly approvalId: string;
      readonly toolCallId: string;
      readonly name: string;
      readonly params: Json;
      readonly requirement: ApprovalRequirement;
    }
  | {
      readonly type: "approval-resolved";
      readonly approvalId: string;
      readonly toolCallId: string;
      readonly approved: boolean;
      readonly reason?: string | undefined;
    }
  | {
      readonly type: "response-complete";
      readonly finishReason?:
        | "stop"
        | "length"
        | "content-filter"
        | "tool-calls"
        | "error"
        | "pause"
        | "other"
        | "unknown"
        | undefined;
      readonly usage?:
        | {
            readonly inputTokens: {
              readonly uncached?: number | undefined;
              readonly total?: number | undefined;
              readonly cacheRead?: number | undefined;
              readonly cacheWrite?: number | undefined;
            };
            readonly outputTokens: {
              readonly total?: number | undefined;
              readonly text?: number | undefined;
              readonly reasoning?: number | undefined;
            };
          }

    };
```

Serializable form of a Turn event. Approval callbacks are dropped, `approval-resolved` records
each decision, and Tool params or results that are not JSON become `null`. Persisted through
`TranscriptStore.appendEvent` inside a
[`TranscriptEventRecord`](/docs/reference/api/core#transcripteventrecord).

### ValidProviderId

```ts
type ValidProviderId<Id extends string> = Id &
  (Id extends "" | `${string}/${string}` ? never : unknown);
```

Constrains a Provider id literal so it can form a Qualified Model id.

Shaped as an intersection rather than a bare conditional so it stays idempotent:
`Id & ValidProviderId<Id>` collapses back to `ValidProviderId<Id>`, which is what lets wrapper
factories forward an unresolved `Id` into [`makeProvider`](/docs/reference/api/core#makeprovider).

### TranscriptMessageSchema

```ts
const TranscriptMessageSchema: Schema.Union<
  [
    Schema.Struct<{
      role: Schema.Literal<"system">;
      content: Schema.String;
      options: optional<ProviderOptions>;
    }>,
    Schema.Struct<{
      role: Schema.Literal<"user">;
      content: Schema.$Array<UserPart>;
      options: optional<ProviderOptions>;
    }>,
    Schema.Struct<{
      role: Schema.Literal<"assistant">;
      content: Schema.$Array<AssistantPart>;
      options: optional<ProviderOptions>;
    }>,
    Schema.Struct<{
      role: Schema.Literal<"tool">;
      content: Schema.$Array<ToolPart>;
      options: optional<ProviderOptions>;
```

Schema of one committed Message; file data is stored as a string, base64, or URL. Decodes to
[`TranscriptMessage`](/docs/reference/api/core#transcriptmessage).

Part unions per role:

- `UserPart`: `text` or `file`.
- `AssistantPart`: `text`, `reasoning`, `file`, `tool-call`, `tool-result`, or

`data: { encoding: "string" | "base64" | "url"; value: string }`; `base64` values must decode
and `url` values must parse as absolute URLs. `tool-call` and `tool-result` parts carry `params`
and `result` as [`Json`](/docs/reference/api/core#json) plus an optional `providerExecuted` flag.

## Functions

### configDirectory

```ts
function configDirectory(
  env?: Readonly<Record<string, string | undefined>>,
  platform?: string,
): string | undefined;
```

Resolves Mitome's shared config directory (`$MITOME_HOME` verbatim, else
`$XDG_CONFIG_HOME/mitome`, with APPDATA/HOME fallbacks). Consumers store their own files under
it: the CLI's default `index.ts` and `.env`, and provider-owned credential stores like
`auth.json`. Undefined when no config root is set. `env`/`platform` are injectable so tests need
no process globals; they default to `process.env` and `process.platform`.

### createHostSession

```ts
function createHostSession(
  context: ChannelHostContext,
): Effect.Effect<Session, AgentDefinitionError | TurnError, Scope.Scope>;
```

Opens the scoped Session a Host runs for its context; closing the Scope ends the Session.
Equivalent to [`createSession`](/docs/reference/api/core#createsession) with the context's `agent`
and `transcripts`.

Returns an Effect yielding a [`Session`](/docs/reference/api/core#session).

### createSession

```ts
function createSession<const Definition extends AgentDefinition>(
  definition: Definition,
  options?: CreateSessionOptions,
): Effect.Effect<Session<ProvidersOf<Definition>>, AgentDefinitionError | TurnError, Scope.Scope>;
```

Compiles the Agent Definition, acquires Extension Resources, and runs `sessionStart` Hooks. The
Session lives until the enclosing Scope closes, which runs `sessionEnd` Hooks and releases
Resources in reverse Agent Definition order. `ProvidersOf<Definition>` is the Definition's
`providers` tuple, so `runTurn` overrides are checked against its catalogs.

Returns an Effect yielding a [`Session`](/docs/reference/api/core#session); fails with
[`AgentDefinitionError`](/docs/reference/api/core#agentdefinitionerror) when the Definition does
not compile and [`TurnError`](/docs/reference/api/core#turnerror) when Extension setup or a
`sessionStart` Hook fails.

### credentialDescriptor

```ts
function credentialDescriptor(provider: AnyProvider): CredentialDescriptor | undefined;
```

Returns a Provider's declarative Credential metadata without provisioning a Model.

Returns a [`CredentialDescriptor`](/docs/reference/api/core#credentialdescriptor), or `undefined`
when the Provider declared none or was not created by this copy of Core.

```ts
  const DefaultModel,
  const Extensions extends ReadonlyArray<AnyExtension>,
>(definition: {
  readonly providers: Providers;
  readonly model: DefaultModel;
  readonly extensions: Extensions;
  readonly approvals?: ApprovalPolicy<NoInfer<Extensions>> | undefined;
}): AgentDefinition<Extract<Providers, ReadonlyArray<AnyProvider>>, DefaultModel, Extensions>;
```

Declares an Agent from its Providers, Default Model, and optional Extensions. The Default Model
is checked against the registered Providers' catalogs at the type level while still accepting
any `provider/model` id for a registered Provider, because catalogs are hints, not allow-lists.
In both overloads `DefaultModel` is constrained to
[`QualifiedModelId`](/docs/reference/api/core#qualifiedmodelid) of the given Providers, and a
`providers` element that is not a Provider makes the call a type error. The second overload
declares an Agent with Extensions; its `approvals` completions know those Extensions' Tool names.

Returns an [`AgentDefinition`](/docs/reference/api/core#agentdefinition) with `extensions`
defaulted to `[]` when omitted.

### defineExtension

```ts
function defineExtension<const LayerValue extends Layer.Layer<any, any, never>>(
  extension: ToolkitlessExtension<LayerValue> & { readonly resource: LayerValue },
): Extension<Layer.Success<LayerValue>, Layer.Error<LayerValue>>;

function defineExtension(extension: ResourceFreeToolkitlessExtension): Extension<never, never>;

function defineExtension<const ToolkitValue extends Toolkit.Any>(
  extension: ToolkitExtension<ToolkitValue>,
): Extension<never, never, ToolkitContributions<Toolkit.ToolsByName<Toolkit.Tools<ToolkitValue>>>>;

function defineExtension<
  const LayerValue extends Layer.Layer<any, any, never>,
  const ToolkitValue extends Toolkit.Any,
>(
  extension: ResourcefulToolkitExtension<LayerValue, ToolkitValue>,
): Extension<
  Layer.Success<LayerValue>,
  Layer.Error<LayerValue>,
  ToolkitContributions<Toolkit.ToolsByName<Toolkit.Tools<ToolkitValue>>>
>;
```

Declares an Effect-native Extension. Each overload accepts the
[`Extension`](/docs/reference/api/core#extension) fields that make sense for its shape and rejects
the rest at the type level:

- Resource, no Tools: Hooks use a Resource `Layer`. The Layer is built when a Session starts and
  released, in reverse order, when its scope closes. A Layer typed `any` is rejected.
- No Resource, no Tools: Instructions and Hooks only.
- Tools, no Resource: contributes an Effect `Toolkit`. Every Tool needs a handler, and handlers
  may not require services the Extension does not provide.
- Resource and Tools: Toolkit handlers and Hooks share one Resource `Layer`. Service requirements
  the Layer does not satisfy are rejected at the type level.

The value is returned unchanged; the overloads exist to compute the Extension's Resource, error,
and [`ToolContributions`](/docs/reference/api/core#toolcontributions) types.

### fileRoutes
