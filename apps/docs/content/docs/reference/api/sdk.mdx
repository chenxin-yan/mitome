Promise-first application surface: define Agents and Extensions, run Sessions, and persist
Transcripts without any Effect type in a public signature.

## Classes

### AgentDefinitionError

The Agent Definition cannot compile: duplicate Provider ids, a malformed or unregistered Default
Model, conflicting Extension or Tool names, Tool handlers without a matching Tool, or malformed
`approvals` rules. `issues` lists every problem found, not just the first.

```ts
class AgentDefinitionError extends Error {
  readonly _tag: "AgentDefinitionError";
  /** Every problem found, at least one. */
  readonly issues: readonly [string, ...string[]];
  /** Every issue, one per line. */
  readonly message: string;
}
```

### ApprovalResolutionError

An Approval decision could not be applied: it was already resolved, or (`reason: "not-pending"`)
its Turn has ended. Decisions are one-shot.

```ts
class ApprovalResolutionError extends Error {
  readonly _tag: "ApprovalResolutionError";
  readonly reason?: "not-pending";
  /** Description derived from `reason`. */
  readonly message: string;
}
```

### SessionBusyError

Overlapping `Session.runTurn()` while a Turn is active.

```ts
class SessionBusyError extends Error {
  readonly _tag: "SessionBusyError";
  /** Fixed description; the error carries no fields. */
  readonly message: string;
}
```

### SessionReleasedError

Turn requested on a Session whose scope has already closed.

```ts
class SessionReleasedError extends Error {
  readonly _tag: "SessionReleasedError";
  /** Fixed description; the error carries no fields. */
  readonly message: string;
}
```

### StoreError

A Transcript store operation failed. From `save` or a mid-Turn `appendEvent`, the Turn fails
before commit. From the `appendEvent` of the final `response-complete` record, the Turn is already
committed and the failure surfaces to the consumer instead of `response-complete`.

```ts
class StoreError extends Error {
  readonly _tag: "StoreError";
  readonly message: string;
  /** The cause of the error. */
  readonly cause?: unknown;
}
```

### TranscriptNotFound

No Transcript exists for the requested id.

```ts
class TranscriptNotFound extends Error {
  readonly _tag: "TranscriptNotFound";
  readonly id: string;
}
```

### TurnError

A model, Tool, or Extension Hook failed while completing a Turn.

```ts
class TurnError extends Error {
  readonly _tag: "TurnError";
  /** Names the failed stage, such as `Turn start Hook failed`, or the Model error's reason. */
  readonly message: string;
  /** The cause of the error. */
  readonly cause: unknown;
}
```

## Interfaces

### AgentDefinition

A user-authored declaration of exactly one Agent: its Providers, Default Model, and Extensions.
Create it with [`defineAgent`](#defineagent); a Session compiles it once when it starts.

### ApprovalRules

Tool-name patterns per decision: an exact Tool name or a prefix followed by one `*` (`"*"` alone
matches every Tool). A Tool matched by several lists resolves `deny` over `ask` over `allow`.
Known Tool names of the Extensions are offered as completions; any string is accepted.

participate in the Agent lifecycle. Identity is the object reference; `name` only labels
diagnostics, and two different named Extensions with the same name conflict. Application code
creates one with [`defineExtension`](#defineextension); the fields below are the Effect-native
contract it produces, shared with `@mitome/core`.

### ToolBuilder

A Tool declaration function scoped to one Extension Resource. The `tools` callback of
[`ExtensionDefinition`](#extensiondefinition) and [`defineAgent`](#defineagent) receives one as
`scope.tool`; which overload applies depends on the schemas the definition declares.

```ts
interface ToolBuilder<Resource = never> {
  /** With `outputSchema` and `failureSchema`: the handler returns `ok()` or `fail()`, both validated. */
  <Input, Output, Failure, const Name extends string>(definition: {
    readonly name: Name;
    readonly description?: string;
    readonly inputSchema: InputSchema<Input>;
    readonly needsApproval?: Tool<Input>["needsApproval"];
    readonly outputSchema: OutputSchema<Output>;
    readonly failureSchema: OutputSchema<Failure>;
    readonly handler: (
      input: Input,
      context: HookContext<Resource>,
    ) => Promise<ToolSuccess<Output> | ToolFailure<Failure>>;
  }): Tool<Input, Output, Failure, Resource, Name>;

  /** With `outputSchema` only: the handler returns the output, which is validated. */
  <Input, Output, const Name extends string>(definition: {
    readonly name: Name;
    readonly description?: string;
    readonly inputSchema: InputSchema<Input>;
    readonly needsApproval?: Tool<Input>["needsApproval"];
    readonly outputSchema: OutputSchema<Output>;
    readonly handler: (input: Input, context: HookContext<Resource>) => Promise<Output>;
  }): Tool<Input, Output, never, Resource, Name>;

  /** Without schemas: the output is inferred from the handler and passed through unvalidated. */
  <Input, Output, const Name extends string>(definition: {
    readonly name: Name;
    readonly description?: string;
    readonly inputSchema: InputSchema<Input>;
    readonly needsApproval?: Tool<Input>["needsApproval"];
    readonly handler: (input: Input, context: HookContext<Resource>) => Promise<Output>;
  }): Tool<Input, Output, never, Resource, Name>;
}
```

Returns a [`Tool`](#tool).

## Type Aliases

### AnyExtension

```ts
type AnyExtension = Extension<any, unknown, any> | Extension<never, any, any>;
```

Any Extension regardless of its Resource. Layer's ROut is contravariant while hook/handler
Effects are covariant in R, so no single parameterization accepts every Extension; the union's
arms cover both variance directions.

### AnyProvider

```ts
type AnyProvider = Provider<string, ReadonlyArray<string>>;
```

Any configured Provider, for code that holds Providers without knowing their catalog.

### AnyTool

```ts
type AnyTool = Omit<Tool<any, any, any, any>, "handler"> & {
  /** Erased handler; see `Tool.handler` for the contract. */
  readonly handler: (...args: never[]) => Promise<any>;
};
```

Any Promise Tool regardless of its input, output, failure, or Resource types.

### ApprovalPolicy

```ts
type ApprovalPolicy<Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>> =
  ApprovalRules<Extensions> | ApprovalPolicyCallback<Extensions>;
```

The Agent author's sparse Approval override: Tools it does not mention keep their author's
`needsApproval` default. `deny` and `ask` always hold; `allow` only bypasses the Tool default and
never an Extension veto or `"ask"`.

### ApprovalPolicyCall

```ts
// Widened form; see below for when `name` and `params` narrow.
type ApprovalPolicyCall<
  Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>,
> = {
  readonly name: string;
  readonly params: unknown;
  readonly toolCallId: string;
};
```

The Tool call an `approvals` callback decides on; `params` is the decoded Tool input. When every
Extension's Tool names are known at the type level, comparing `name` narrows `params` to that
Tool's input; one Extension typed without contributions leaves `name: string` and
`params: unknown` for the whole call, since its Tools reach the callback too.

### ApprovalPolicyCallback

```ts
type ApprovalPolicyCallback<
  Extensions extends ReadonlyArray<AnyExtension> = ReadonlyArray<AnyExtension>,
> = (call: ApprovalPolicyCall<Extensions>) => ApprovalPolicyDecision | undefined;
```

Synchronous, param-aware Approval rule. Throwing, returning a Promise or Effect, or returning
anything other than a decision or `undefined` fails the Turn before the Tool runs.

### ApprovalPolicyDecision

```ts
type ApprovalPolicyDecision = "allow" | "ask" | "deny";
```

The Agent author's opinion on one Tool call; `undefined` defers to the Tool's `needsApproval`.

### ApprovalRequirement

```ts
type ApprovalRequirement = "tool" | "policy" | "predicate-error";
```

Why a Tool call paused for Approval: the Tool author's `needsApproval` (`tool`), the Agent's
`approvals` or an Extension `preTool` `"ask"` (`policy`), or a `needsApproval` predicate that
failed and therefore fails closed (`predicate-error`).

### FinishReason

```ts
type FinishReason =
  "stop" | "length" | "content-filter" | "tool-calls" | "error" | "pause" | "other" | "unknown";
```

Why the Model stopped generating in a Step.

### InputSchema

```ts
type InputSchema<Input = unknown> =
  (StandardSchemaV1<unknown, Input> & StandardJSONSchemaV1<unknown, Input>) | EffectSchema<Input>;
```

Schema for Tool input: a Standard Schema that also emits JSON Schema (zod v4 does), or an Effect
Schema. The Model needs the JSON Schema; the validator decodes what it sends back. `EffectSchema`
is a structural view of an Effect `Schema` so that no Effect type appears in this signature.

### Json

```ts
type Json = null | boolean | number | string | ReadonlyArray<Json> | { [key: string]: Json };
```

A JSON-serializable value.

### OutputSchema

```ts
type OutputSchema<Output = unknown> = StandardSchemaV1<unknown, Output> | EffectSchema<Output>;
```

Schema for a Tool's output or expected failure; validation only, no JSON Schema needed.

## Functions

### defineAgent

```ts
function defineAgent<
  const Providers extends ReadonlyArray<AnyProvider>,
  const DefaultModel extends QualifiedModelId<Providers[number]>,
  const Extensions extends ReadonlyArray<AnyExtension> = readonly [],
>(definition: {
  readonly providers: Providers;
  readonly model: DefaultModel;
  readonly extensions?: Extensions;
  readonly approvals?: ApprovalPolicy<Extensions>;
}): AgentDefinition<Providers, DefaultModel, Extensions>;

function defineAgent<
  const Providers extends ReadonlyArray<AnyProvider>,
  const DefaultModel extends QualifiedModelId<Providers[number]>,
  const Extensions extends ReadonlyArray<AnyExtension> = readonly [],
  const Tools extends ReadonlyArray<AnyTool> = readonly [],
>(definition: {
  readonly providers: Providers;
  readonly model: DefaultModel;
  readonly extensions?: Extensions;
  readonly tools: (scope: { readonly tool: ToolBuilder<never> }) => Tools;
  readonly approvals?: ApprovalPolicy<
    readonly [...Extensions, Extension<never, unknown, ToolContributionsOf<Tools>>]
  >;
}): AgentDefinition<
  Providers,
  DefaultModel,
  readonly [...Extensions, Extension<never, unknown, ToolContributionsOf<Tools>>]
>;
```

Declares an Agent from its Providers, Default Model, and optional Extensions. The Default Model is
a Qualified Model id (`provider/model`) whose prefix must name a registered Provider; catalog ids
are offered as completions but any model id under that Provider is accepted. `approvals` offers
the Extensions' Tool names as completions; see [`ApprovalPolicy`](#approvalpolicy).

The second overload declares an Agent with one-off Tools that need no Resource. The `tools`
builder becomes an anonymous Extension appended after `extensions`; use
[`defineExtension`](#defineextension) when Tools need a Resource, Hooks, Instructions, or reuse. An
`approvals` callback narrows `params` by inline Tool name only when it is written after `tools`;
rule lists complete inline names in any order.

Returns an [`AgentDefinition`](#agentdefinition). Definition problems surface as
[`AgentDefinitionError`](#agentdefinitionerror) when a Session compiles it.

### defineExtension

```ts
function defineExtension<Resource = never>(
  definition: ExtensionDefinition<Resource, readonly []>,
): Extension<Resource, unknown, ToolContributionsOf<readonly []>>;

function defineExtension<Resource = never, const Tools extends ReadonlyArray<AnyTool>>(
  definition: ExtensionDefinition<Resource, Tools> & {
    readonly tools: (scope: { readonly tool: ToolBuilder<Resource> }) => Tools;
  },
): Extension<Resource, unknown, ToolContributionsOf<Tools>>;
```

Declares a Promise Extension without Tools: Instructions, Hooks, and an optional Resource. A
Resource is private to its Extension, so put Hooks that share state in one Extension. The second
overload declares a Promise Extension with Tools. Tool names must be unique within the Extension,
and `dispose` requires `setup`; both throw at definition time.

When `Resource` is anything other than `never`, `setup` is required; when it is `never`, `setup`
and `dispose` must be omitted. The compiler enforces this on the `definition` parameter.

Returns an [`Extension`](#extension).

### defineMitome

```ts
function defineMitome<const Agent extends AgentDefinition>(definition: {
  readonly agent: Agent;
  readonly hosts?: ReadonlyArray<{ readonly kind: "interactive" | "channel" }>;
  readonly transcripts?: TranscriptStore;
}): MitomeDefinition<Agent>;
```

Creates a Mitome Definition. Omit `hosts` for one-shot use; a value that is not a Host, such as an
uncalled factory, throws. Omit `transcripts` to write no Transcript data; when given, every Host
shares that store.

Returns a [`MitomeDefinition`](#mitomedefinition).

### fail

```ts
function fail<const Failure>(error: Failure): ToolFailure<Failure>;
```

Wraps an expected failure the Model should see and react to; it is validated against
`failureSchema`. Throwing instead is a defect and yields an opaque failed result.

Returns a [`ToolFailure`](#toolfailure).

### fileTranscripts

```ts
function fileTranscripts(directory?: string): TranscriptStore;
```

Disk-backed store rooted at `directory`, defaulting to `<config-dir>/transcripts`; files are
created with mode 0600. Throws immediately when no directory is given and no config directory
resolves (set `MITOME_HOME`).

Returns a [`TranscriptStore`](#transcriptstore).

### memoryTranscripts

```ts
function memoryTranscripts(): TranscriptStore;
```

In-memory store for tests or a shared store without disk writes. Contents live as long as the
returned value; event records are discarded.

Returns a [`TranscriptStore`](#transcriptstore).

### ok

```ts
function ok<const Output>(value: Output): ToolSuccess<Output>;
```

Wraps a Tool result as an expected success; required when the Tool declares a `failureSchema`.

Returns a [`ToolSuccess`](#toolsuccess).

### withSession

```ts
function withSession<const Definition extends AgentDefinition, A>(
  definition: Definition,
  use: (session: Session<Definition["providers"]>) => Promise<A>,
): Promise<A>;

function withSession<const Definition extends AgentDefinition, A>(
  definition: Definition,
  options: SessionOptions,
  use: (session: Session<Definition["providers"]>) => Promise<A>,
): Promise<A>;
```

Opens a Session for the Agent Definition, runs the callback, and releases the Session afterwards,
including on failure or interruption. The second overload opens the Session with persistence or
seeding options; see [`SessionOptions`](#sessionoptions).

Returns the callback's result.

Throws the tagged Session errors: [`AgentDefinitionError`](#agentdefinitionerror) when the
definition does not compile, [`TranscriptNotFound`](#transcriptnotfound) when `resume` names an
unknown id, and [`TurnError`](#turnerror), [`StoreError`](#storeerror),
[`SessionBusyError`](#sessionbusyerror), or [`SessionReleasedError`](#sessionreleasederror) while
iterating a Turn. Errors thrown by the callback are rethrown unchanged.
