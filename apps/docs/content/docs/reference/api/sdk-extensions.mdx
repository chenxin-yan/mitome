First-party Extensions that ship with the SDK.

## Interfaces

### InstructionFilesOptions

```ts
type InstructionFilesOptions =
  | {
      readonly base: string;
      readonly paths?: ReadonlyArray<string>;
      readonly discover?: ReadonlyArray<string>;
    }
  | {
      readonly base?: never;
      readonly paths?: ReadonlyArray<AbsolutePath>;
      readonly discover?: ReadonlyArray<string>;
    };

// POSIX-rooted, Windows-rooted or UNC, or a Windows drive path (`DriveLetter` is `a`-`z`, `A`-`Z`).
type AbsolutePath =
  `/${string}` | `\\${string}` | `${DriveLetter}:/${string}` | `${DriveLetter}:\\${string}`;
```

Options for `instructionFiles`. Relative `paths` need `base`, the calling module's `import.meta.url`,
and resolve against its directory; absolute `paths` and `discover` do not. The host platform's
`path.isAbsolute` still applies at runtime, so a Windows form on POSIX throws. `discover` names bare
filenames looked up in every directory from the git root down to the working directory.

## Functions

### instructionFiles

```ts
function instructionFiles(options?: InstructionFilesOptions): Extension;
```

Creates an Extension whose Instructions are read from files when the definition loads. A missing
`paths` entry throws; missing `discover` names are skipped.

Returns an [`Extension`](/docs/reference/api/sdk#extension).

### instructions

```ts
function instructions(text: string): Extension;
```

Creates an Extension with a static inline Instructions fragment.

Returns an [`Extension`](/docs/reference/api/sdk#extension).
