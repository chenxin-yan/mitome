# @mitome/providers

Current first-party Provider subpaths: `@mitome/providers/anthropic`, `@mitome/providers/openai`, `@mitome/providers/openai-compatible`, and `@mitome/providers/openai-codex`. There is no root import. Codex uses an unofficial ChatGPT endpoint and remains best-effort.

Each factory returns a `@mitome/core` Provider to list in a Configuration, for example `Mitome.make({ agent, providers: [openai()], model: "openai/gpt-5.6" })`; see [Agents and Configurations](https://mitome.sh/docs/agents). `openai()` and `anthropic()` read their API key from `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` (or the variable named by `apiKeyEnv`), and `openaiCompatible()` from its `apiKeyEnv` when one is given. They read it from the process environment by default, unless a supplied Effect `ConfigProvider` supplies it. Absent or empty input fails provisioning the Model with `MissingCredentialError`, exported from those three subpaths; an error of the configuration source stays a `ConfigError`. Anthropic takes an API key only: signing in through the Claude Console profile is not implemented yet. Authenticate Codex by running the Effect its `login` export returns or, from the Mitome CLI, `mitome auth login --provider openai-codex`; Credentials live in the Mitome state directory: direct `login` and `logout` callers must pass a resolved `stateDirectory`; only `codex()` defaults it, and needs the option only when the directory differs from that default.

Anthropic sends Tools without strict schema validation, because a request may carry at most 20 strict Tools; annotate a Tool with `Tool.Strict` to make it strict. `generateObject` still asks capable Models for Anthropic's native JSON output format.
