# @mitome/providers

Current first-party Provider subpaths: `@mitome/providers/anthropic`, `@mitome/providers/openai`, `@mitome/providers/openai-compatible`, and `@mitome/providers/openai-codex`. There is no root import. Codex uses an unofficial ChatGPT endpoint and remains best-effort.

Each factory returns a `@mitome/core` Provider to list in a Configuration, for example `Mitome.make({ agent, providers: [openai()], model: "openai/gpt-5.6" })`; see [Agents and Configurations](https://mitome.sh/docs/agents). `openai()` and `anthropic()` read their API key from `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` (or the variable named by `apiKeyEnv`), and `openaiCompatible()` from its `apiKeyEnv` when one is given. They read it from the process environment by default, unless a supplied Effect `ConfigProvider` supplies it. Absent or empty input (and, for Anthropic, no Claude Console sign-in either) fails provisioning the Model with `MissingCredentialError`, exported from those three subpaths; an error of the configuration source stays a `ConfigError`. Authenticate Codex by running the Effect its `login` export returns or, from the Mitome CLI, `mitome auth login --provider openai-codex`; Credentials live in the Mitome state directory: direct `login` and `logout` callers must pass a resolved `stateDirectory`; only `codex()` defaults it, and needs the option only when the directory differs from that default. A Codex token exchange (sign-in or refresh) never follows a redirect: a 3xx answer fails it, and the redirect target receives nothing.

Anthropic sends Tools without strict schema validation, because a request may carry at most 20 strict Tools; annotate a Tool with `Tool.Strict` to make it strict. `generateObject` still asks capable Models for Anthropic's native JSON output format.

Anthropic takes either of two Credentials, both billed to a Claude Console organisation at API rates. An API key in `ANTHROPIC_API_KEY` (or the variable `apiKeyEnv` names) wins when it is set. Otherwise `anthropic()` reads the Claude Console sign-in that Anthropic's CLI, [`ant`](https://github.com/anthropics/anthropic-cli), writes to a named profile in Anthropic's config directory, found as Anthropic's SDK finds it (`ANTHROPIC_CONFIG_DIR`; else, on Windows, `%APPDATA%\Anthropic`, or `%USERPROFILE%\AppData\Roaming\Anthropic` without `APPDATA`; elsewhere `$XDG_CONFIG_HOME/anthropic`, else `~/.config/anthropic`), and refreshes its token as Anthropic's SDK does, under a lock beside the credentials file. It reads the named profile only: `ant`'s active profile, `ANTHROPIC_PROFILE` and the SDK's environment fallbacks for the workspace and API host are not consulted. The profile is `mitome` unless the `profile` option names another, so signing in does not touch the `default` profile Claude Code shares. Sign in with `ant auth login --profile=mitome` or, from the Mitome CLI, `mitome auth login --provider anthropic`, which runs `ant` for the Provider's profile; `ant` then also makes that profile its active one, which other Anthropic tools that name no profile follow (`ant profile activate <name>` switches back). The profile's tokens go only to an https host, or to http on this machine; a `base_url` or `baseUrl` that is set but unusable is an error, never a fallback to another host. The refresh token goes only to the host that issued it, the profile's `base_url` or else Anthropic's API, never to the host of the `baseUrl` option, which receives only the access token with Model requests. Since `ant` takes no lock, Mitome reads the profile's config again after its credentials and leaves credentials `ant` replaced or removed during a refresh as they are, but a change `ant` makes between Mitome's last read and its use or rewrite of the credentials can still be missed or overwritten. A profile with no credentials (never signed in, or signed out) fails provisioning with `MissingCredentialError`; a profile that exists but cannot be used fails provisioning with `UnusableProfileError`, and one that stops being usable during a Session (an expired sign-in, a changed profile) fails the request with an `AiError`; each message says what to fix. Mitome runs no OAuth flow of its own and holds no client id. The Claude subscription sign-in (claude.ai) is not supported: Anthropic does not permit third-party applications to offer it.
