"@mitome/core": minor
---

Add `@mitome/core`, the Effect-native conversation kernel. `Session.make`, `step`, `loop` and `localTools` come from its subpath `@mitome/core/kernel`, the layer under an Agent. `Session.make({ transcript, limits })` allocates a fresh scoped Session on an explicit `Transcript`, opened at its stored position, or with `"none"` on one the kernel keeps in memory; `session.run(program)` runs any Effect as one Turn, preserving its result, error and requirement types. The conversation holds plain data, never live objects: a Tool's schema turns a live value into data, the kernel checks at the door and serialises nothing, and each store chooses its own format. Plain data is JSON as Effect's `Schema.Json` defines it, and `isPlainData` is that check: `null`, booleans, finite numbers, strings, and arrays and plain records of them; a record field of `undefined` is not plain data, so `isPlainData({ a: undefined })` is false. A staged Message is kept as a copy of its encoded form without record fields of `undefined` and with negative zero as zero, which is what any store reads back, and only if that copy is plain data; the copy is a snapshot, so later reads of it never consult the original getter or `Proxy`, and later changes to the original reach nothing kept; anything else is a defect of its stager that names the Message's role and where the value is. A Model response whose contribution to the conversation, Tool Call parameters included, is not plain data fails its Step with `StepProtocolError` before any policy, Approver or Tool runs, and a Tool result whose encoded form is not (a loose schema such as `Schema.Any` let a live value through) is a defect naming the Tool. History is a tree of Entries: each controlled Step that completes commits the Messages the ambient `Turn` has staged as one Entry under the position, stored by the Transcript before it is published, and Messages still staged when the program and its cleanup succeed commit as a last Entry; a Turn that fails or is interrupted keeps the Entries it committed and drops what it still had staged. `session.history` is the current Branch, `session.position` the Entry the next commit goes under, `session.moveTo(id)` moves it (refused while a Turn runs) so the next Turn branches from there, `session.tree` lists every Entry, and `session.transcript` is the id of the Transcript, which every Transcript has, the kernel's in-memory one included. The Turn also exposes its owning Session, drains the program's child fibers before its Scope closes and child fibers forked by its cleanup before its last commit (a finalizer must join a child that needs resources later finalizers release; work a finalizer forks into the closing Turn Scope itself with `Effect.forkScoped` never starts, because that Scope is already closed). When the Turn's own cleanup dies, a typed failure of the program reaches the caller as a defect too, as Effect treats any Cause that contains a defect. A failed commit or move fences the Session with `SessionFencedError` when its cause is empty or is not made entirely of definite `not-written` `SessionSaveError` failures, so a `conflict` (another writer moved the stored position) or an `unknown` outcome fences it, as does an adapter method that throws instead of returning an Effect; a fenced Session admits no further Step, before its Model request. A Turn ends, and a Session is released, only after a commit already started has settled, and release also waits for a move under way and interrupts a `tree` read. A Turn's snapshot says whether it `succeeded`, `failed` or is `uncertain` (a commit it made fenced the Session) and lists the Entries it committed. `limits` bounds each Turn's controlled Model generations and local Tool dispatches with `ExecutionLimits`, `{ generations, dispatches }`, each a non-negative integer; a bound left out is no limit, any other key is refused, and a Session made without `limits` has none.

Controlled Steps run inside a Turn.

- `step` runs one generation with native Tool resolution disabled. It validates the whole response before any local handler runs and returns either a complete result (the original native response plus separately resolved local Tool results) or an `Incomplete` value that dispatched, staged and committed nothing. A complete Step commits what is staged as its Entry, and none when there is nothing to commit (a Turn's `entries` are the ids it committed, not one per Step), and a commit that fails fails the Step with `SessionSaveError` or `SessionFencedError`. `loop` repeats the same Step and fails with `IncompleteStepError` on incomplete output. Malformed or unsupported responses fail with `StepProtocolError`, and native approval parts in the Model Context are rejected before generation.
- Steps of one Turn are admitted one at a time; a Step started from its own callbacks is rejected as a defect instead of waiting forever.
- `localTools` registers native Tools and handlers once. A local Tool result's `encodedResult` is encoded with the Tool's JSON codec; `Schema.Void` now encodes as `null`. A Tool's `toModelOutput` is what the Model is sent in place of that result. Provider-defined, dynamic and client-executed Tools are rejected at registration. Each call is decided once by `policy` or the Tool's own risk flag, tightened by any `restrictions` (the strictest decision wins: deny over ask over allow), answered by the `Approver` when asked and run serially. A failure, defect or synchronous throw from any of them denies; interruption propagates. Policy, restrictions and the Approver run with exactly the Step caller's services, never those the Tools were registered with.
- Plain objects and arrays in the decoded arguments are deeply frozen before the first callback sees them, and the handler receives that same value, so they stay exactly as policy decided whatever a callback attempts: a write in sloppy mode or through `Reflect.set` is ignored, and a write that throws out of a callback denies the call. Values that are not plain data, such as a `Date` decoded by `Schema.DateFromString`, a `Map` or a class instance, are not frozen, and a callback that mutates one changes what the handler receives.
- Only the gate reaches the `Approver`: Tool handlers and `restrictions` see nobody, so Tool or Extension code cannot ask a person for an Approval the gate did not check.
- `Approver` is the service that answers a pending Approval with `decide(request)`, where the request carries the Turn id, Tool-call id, Tool name and the parameters as the JSON the Model sent (`Schema.Json`), without fields the Tool does not declare, not the value the Tool's schema decodes from them, which policy and the handler receive. A Host provides it; with nobody present an ask is denied with "Tool call needs approval and nobody is present to give it".
- Every denial reaches the Model as a failed Tool result carrying the native `AiError` and its reason, whatever the Tool's failure mode or failure schema, and the Step continues: the denial is encoded with the `AiError` JSON codec, not the Tool's. The failure mode and the Tool's codec still govern the handler's own failures; reaching the dispatch limit still fails the Step with `ExecutionLimitError`.
- A Step requires `ModelRequestAccounting` for the exact Model in use; `withModelRequestAccounting` and `Provider.model` build it. `Turn.usage` is readable while the Session lives, and a Turn handle that escapes its Turn can no longer start generations or dispatch Tools.

`Provider.make(id, { modelIds, credential, provision, models })` creates a Provider contract value whose type keeps its provisioning Layer's error and requirements, with an optional `credential` descriptor and optional per-Model `{ contextWindow }` metadata in `models`; `Provider.model` builds its accounted Model binding and `Provider.credentialDescriptor` reads its Credential metadata. `configDirectory()` and `stateDirectory()` resolve Mitome's config and state directories (`$MITOME_HOME`, else the XDG directory, with Windows and home fallbacks); an Auth capability's `authenticate` returns an Effect that needs no service, reads lines through the `input` Effect and stores Credentials under `AuthenticateOptions.stateDirectory`.

A `SessionSaveError` carries a `cause` when the store knows why, and its message ends with it. The kernel errors (`SessionBusyError`, `SessionReleasedError`, `SessionFencedError`, `SessionSaveError`, `TranscriptError`, `ExecutionLimitError`, `StepProtocolError`, `ToolRegistrationError`, `IncompleteStepError`) are nominal types: a structurally identical value is not accepted where one is expected.
