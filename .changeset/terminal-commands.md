The terminal runs Commands and takes its keys from the Configuration. Bare `mitome` reads the terminal's options the Configuration provides (`terminal({ keys })` from `@mitome/core/terminal`) and does not open without them, without a key bound to `terminal.submit`, or with a key it refuses, saying what to add or change: `ctrl+c` and `tab`, which stay fixed, and a letter, digit or `space` with no modifier or only `shift`, which would take the key from typing. A key a terminal reports only with the enhanced keyboard protocol, such as `shift+enter`, is accepted; without the protocol it arrives as another key, so Shift+Enter sends. Only bound keys send, start a new line or interrupt: the editor's own Enter and Alt-Enter no longer do. A key bound to text acts as if it were typed into an empty editor and sent, keeping the draft. An input that `Command.parse` names a Command runs it: the terminal's own `/quit` closes it as Ctrl-C does and `/new` starts a new conversation for the working directory; any other name runs the Session's Command, whose reply is shown and kept out of the conversation and whose prompt runs as a Turn through `text.parse`, and an unknown or failing Command is shown without reaching the Model. While the input starts with `/`, the terminal lists the matching Commands with their descriptions, as many as leave the editor on the screen. `/new` switches only to a conversation whose Extensions name no `/quit` or `/new`, and keeps the current one otherwise. A key is also looked up as the Latin key at its place on another layout. An Extension that names a Command `quit` or `new` keeps the terminal from opening.

`mitome init` writes the starter keys into `index.ts`: `enter` sends, `shift+enter` and `ctrl+j` start a new line (Ctrl+J in every terminal), `escape` interrupts and `ctrl+d` types `/quit`.
