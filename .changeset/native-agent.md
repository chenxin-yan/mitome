Describe an Agent as data and run it through a Configuration.

- `Extension.make(name, parts)` names what an Extension adds, `{ instructions, tools, handlers, policy, commands }`, given as a record or as an Effect that returns one, its setup. A record is validated when the Extension is made and kept as a frozen copy, with its own copies of the handler map (a plain map, given exactly with `tools` and matching its Toolkit) and the Command list; the Extension is `{ name, parts }`. A setup runs once each time a Session is made from the Agent, in that Session's Scope, so what it acquires lives until the Session closes and state it keeps is its own local variable, which its handlers, policy and Commands close over; its record is validated then. `Agent.make({ instructions, use, policy, limits, program, text })` reads each field once, inherited ones included, validates them and returns them frozen, with its own copies of `use` and the limits; nothing is run or registered until the Agent runs. Without `limits` the Agent's Turns have no limit; a key in `limits` that names no bound is refused, so a misspelled one cannot silently leave a count unlimited. `Agent.make` checks its limits and throws when two Extensions share a name, or when two given as records define a Tool or a Command of the same name. `Agent.make({ ...agent, instructions })` overrides part of an Agent.
- `Command.make(name, { description, run })` describes a Command a person invokes by typing `/name`: the name is a lowercase letter followed by at most 30 lowercase letters, digits or underscores, the description one non-empty line of at most 100 characters. `run` takes the text after the name and returns `Command.reply(text)`, text to show, or `Command.prompt(text)`, an input to start a Turn with. `Command.parse(input)` returns the Command an input names, only when its first character is `/` followed by a name and then whitespace or the end.
- When an Agent runs, its Instructions come first and each Extension's follow in `use` order; its Tools are the union of the Extensions' Toolkits; its `policy` decides each Tool Call and every Extension `policy` can only tighten that decision. A `program` receives the standard `step` and `loop` with all of that applied, which die if run in a Turn of another Session; without one, the input is staged as a user Message, `loop` runs and the final text is the result. `text: { parse, render }` is required unless the program accepts any string and returns a string.
- `Session.make(agent)` allocates a Session whose `run(input)` runs the Agent as one Turn. It runs the Extensions' setups one after another in `use` order, on a fiber of their own, and registers their Tools once, each Extension binding only its own Tools, in one Scope the caller's Scope owns; closing it interrupts a setup still running, drains the Session's Turns and Commands and only then releases what the setups acquired, as a construction that fails does. A setup's failure fails it; a malformed setup record, or a Tool or Command name it shares with another Extension, is a defect naming them. What the setups, policies and Commands need is a requirement of `Session.make`, apart from the `Turn` and `Scope` the Step running a policy supplies and the `Scope` each Command call is given; a policy runs with the services of its Step, those `Session.make` had replacing the same ones there; the Model the program needs stays a requirement of `run`. The Session lists its Extensions' Commands in `use` order (`commands`) and runs one by name (`command(name, input)`) with what its setup holds, in a Scope of its own closed when it ends, outside any Turn and whether or not one is running, failing with `CommandNotFoundError` for an unknown name, `CommandFailedError` when `run` fails and `SessionReleasedError` once the Session is released; closing the Session interrupts a running Command before its setup's resources are released. `Session.make` from the root entry takes only an Agent; a Session without one comes from `@mitome/core/kernel`.
- `Mitome.make({ agent, providers, model, provide })` returns the Configuration: those fields plus `protocol: "mitome/1"`, inert `discovery`, the resolved `text` mapping (the identity for text Agents, failing with `TextMappingError` on a non-string result) and `acquire({ provider, model, onShutdown })`. `provide` is one Layer or a non-empty list of independent Layers, each requiring nothing, and when written it holds one, never `undefined`; a list is copied and frozen. An option `Mitome.make` does not know is a type error. The acquired `Mitome.Instance` builds what is provided and provisions the Model once, runs each Session `instance.session(options)` allocates as `Session.make(agent, options)` does, refusing its `command` too once shutdown has begun, and shuts down by closing admission (`MitomeClosedError`) and cancelling and draining work, a Session still being built included, before releasing what it acquired. `MitomeClosedError`, `ModelSelectionError`, `TextMappingError` and `TranscriptSelectionError` are nominal types: a structurally identical value is not accepted where one is expected. A `shutdown` or Session `close` whose caller is interrupted keeps running, so later calls and the owning Scope wait for the same one and `onShutdown` runs once. A construction or startup failure whose release dies reaches the caller as a defect. A failure to provision the configured Model is returned as the Provider's own error. Only a certainly non-empty Provider tuple supplies the Model in the types; at runtime, an acquisition whose provided services and selected Model together provide no `LanguageModel` for an Agent without a `program` fails with `ModelSelectionError` before its first Turn, releasing what it built. The inferred type of an Agent without a `program` can be named in a consumer's declarations.
- `Transcripts` is the service, absent by default, that hands out stored conversations: `create(scope)`, `latest(scope)` and `open(id)`, where the scope is an opaque label the Host chooses. `Session.make(agent, { transcript })` and `instance.session({ transcript })` select a new conversation (the default, under the scope `""`), the latest under a scope or one by id; without the service history stays in memory, and asking for the latest or an id fails with `TranscriptSelectionError`, as it does when there is no such conversation. A Configuration's `provide` provides it, and an acquired Configuration without it keeps history in memory whatever the caller of `session` provides; the Agent's program, its policies, its text mapping, Extension setups, Tool handlers and Commands never see it. A selection names exactly one of `create`, `latest` and `open`.
- A Configuration's `provide` cannot supply the `Approver`, and Extension setups, Tool handlers, Extension policies and Commands never see it; the Host that runs the Turn supplies the Approver. An Extension provides no service to the Agent's program, and its setup and Commands never see a Turn: requiring one is a type error where they are defined.
