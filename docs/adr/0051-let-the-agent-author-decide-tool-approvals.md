# Let the Agent author decide Tool Approvals

Approval authority is layered: Tool authors flag risk with `needsApproval`, Extensions may only tighten, the Agent author decides, and Hosts resolve. The Agent Definition carries an optional `approvals` policy — a sparse rule object `{ allow?, ask?, deny? }` of Tool-name patterns or a synchronous callback `(call) => "allow" | "ask" | "deny" | undefined` — that travels with the Agent through compilation to every Host. Core merges the opinions per Tool call, after input decoding, with the most restrictive winning: any Extension veto or Agent `deny` denies the call and the Model sees a stable, sanitized policy-denial reason; otherwise any Extension `"ask"` or Agent `ask` requires a Host Approval; otherwise an Agent `allow` runs the call without consulting the Tool's `needsApproval`; otherwise the Tool author's default decides. `allow` therefore overrides only the Tool author's default, never an Extension or the Agent's own `deny`/`ask`, and `allow: ["*"]` is the sanctioned way to run unattended.

The decision is computed once per Tool call in the serialized preparation step (ADR-0005) and cached with the prepared call, so Hooks and the policy do not re-run after consent. Patterns are an exact Tool name or a prefix followed by one trailing `*` (`"*"` alone matches every Tool); `compileAgentDefinition` rejects any other use of `*`, unknown rule keys, and non-array lists, and an unmatched valid pattern matches nothing. There is no glob library. The callback is synchronous in v1: a throw, a Promise or Effect return, or any value that is not a decision fails the Turn with `Approval policy failed` before the handler runs, and the raw cause never reaches the Model (ADR-0044).

Every `approval-required` event, live and persisted, carries `requirement: "tool" | "policy" | "predicate-error"` so a Host can distinguish a Tool-flagged ask from an explicit policy ask. `requirement` is a required field of the existing version-1 event record: persisted Approval records written before this change are not decodable, which is acceptable because nothing has shipped. Mitome fails closed when a `needsApproval` predicate fails and asks with `requirement: "predicate-error"`, where Effect's `LanguageModel` fails open; an explicit Agent `allow` skips the predicate, so `predicate-error` only appears when the predicate was actually evaluated.

Placing the override at the Agent level is deliberate. Eve exposes Tool-authored Approval policies for the Agent to adjust, while pi has no built-in Tool Approval gate at all; Mitome keeps the Tool author's flag as the default and gives the Agent author one place to relax or tighten it. This is not a sandbox against arbitrary Host or Extension code: Core enforces deny and veto, and a custom Host remains responsible for its own consent behavior when resolving asks.

## Consequences

- `AgentDefinition.approvals` is a runtime field: `defineAgent` passes it through and `CompiledAgent.approvals` holds it as one callback, with rule objects folded at compile time.
- `preTool` Hooks may return `"ask"` in addition to `{ reason }`; `"ask"` is collected across Extensions while a veto still short-circuits before the Agent policy is evaluated.
- Event logs remain observability data (ADR-0036): `requirement` explains a pause but is not resumable Approval authority.
- Host behavior for policy-origin asks (interactive prompt, one-shot handling) is decided separately; this ADR only guarantees the metadata Hosts need.
