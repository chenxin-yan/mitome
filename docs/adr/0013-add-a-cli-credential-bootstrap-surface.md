# Add a CLI credential bootstrap surface

The CLI gains `mitome auth login [--use <file.ts>]` and `mitome auth logout [--use <file.ts>]`. Login is Definition-scoped: the CLI loads the selected trusted Definition and delegates authentication to the provider of its Model, so the CLI carries no provider registry and Codex code stays out of API-key installs. OAuth providers run their login flow and persist into `auth.json` (ADR-0010); API-key providers prompt for a masked key and write it to `<config-dir>/.env`, sharing one bootstrap implementation with `mitome init`. At startup the CLI — and only the CLI — loads `<config-dir>/.env` into the process environment without overriding existing variables; Core then resolves the Definition's declarative `env("OPENAI_API_KEY")` descriptor from process env, so there is one credential-resolution mechanism with two layers. Embedded SDK sessions read `process.env` untouched. `mitome init` writes the entered key to `<config-dir>/.env` and generates no `.env.example`.
