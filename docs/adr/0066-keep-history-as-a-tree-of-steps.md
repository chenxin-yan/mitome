# Keep history as a tree of Steps, in a store a Configuration provides

A conversation's history is a tree of **Entries**. An Entry is the Messages committed together: normally one Step (the Model's response and the results of the Tool calls it asked for) with whatever the program staged before it, such as the prompt. Each Entry names its parent. The **Execution position** is the Entry the next one goes under; moving it to an earlier Entry and running a Turn makes a Branch. The committed part of a Model Context is always the Messages on the path from the root to the position; a Step still puts the Instructions before them and the Turn's staged Messages after them.

A Turn commits as it goes: each completed Step commits what is staged as an Entry, and Messages still staged when the program succeeds become a last one. A Step with nothing to commit leaves no Entry: the tree is the conversation, and the work is counted on the Turn. A Turn that fails or is interrupted keeps the Entries it committed and drops only what was still staged, so one that fails before its first Step completes leaves nothing. A commit that could not be written fails its Step with a typed error and leaves its Messages staged. This replaces the single commit per Turn of [ADR-0057](0057-use-effect-native-functions-and-optional-host-composition.md) and [ADR-0036](0036-persist-committed-history-as-transcripts.md).

The conversation holds plain data, never live objects: JSON as Effect's `Schema.Json` defines it, that is `null`, booleans, finite numbers, strings, and arrays and plain records of them. Before the check the kernel copies a Message's encoded form without the record fields that are `undefined` and with `-0` as `0`, so that every format keeps the same conversation. The rule is about a Message's encoded form: history and an adapter hold Messages, which can carry bytes, and what the Message codec encodes them to is the plain data. Live values, such as a `Date` or a class instance, are what code works with; a Tool's schema turns them into data, and a store chooses its own format for that data. The kernel checks at the door and serialises nothing. A Message a program stages, a Model's response and a Tool's result are each refused when they hold anything else, with the place and what is there, so that memory and every store hold the same conversation and an adapter is free to write JSON, rows or bytes. The check reads a value as any code would, so a getter or a Proxy that yields JSON is accepted; what the conversation keeps is a snapshot, and later reads of it never consult the original. A Transcript is called by the kernel, which hands it Entries that are already such snapshots. An adapter applies the rule as a guard and does not copy again, so code that calls an adapter directly with an object whose reads change, or throw, gets what its own object did.

A **Transcript** stores one conversation: it gives the position and its Branch when opened, appends an Entry under an expected position and moves the position, and refuses when the stored position is not the expected one. The position is therefore a stored fact, checked on every commit, and a second writer is caught. The check is on the position's identity, not on a revision: a position that moved away and back is accepted, which loses nothing, because an append only ever adds a sibling and each Session's Branch is still what it read. A Transcript answers a failed write as not written, as a conflict or as unknown; only the first leaves the Session usable. A Session with no store keeps the same tree in memory.

Where conversations are kept is a service, `Transcripts`, absent by default: unless a Configuration asks for a store, history lives in memory and ends with the Session, and `mitome init` writes a Configuration without one. A Configuration's `provide` supplies it, and a Host says which conversation a Session uses: a new one, the one most recently written under a label it chooses, or one by id. `@mitome/transcripts` is the first adapter: an append-only JSONL file per conversation under the state directory. `mitome --continue` opens the conversation most recently written under the working directory, and `--continue=<id>` the one with that id.

## Considered options

- **One commit per Turn**, as before. A Turn that is interrupted or fails at its thirtieth Step leaves no trace in the conversation, while the files it changed stay changed; the next prompt goes to a Model that does not know what it did. For an agent whose Turns are long and whose user interrupts routinely, that is the wrong default.
- **One node per Message**, as pi's session file has. A Branch could then start between a Tool call and its result, and the kernel would have to repair or refuse such histories. A Step boundary is always a complete exchange.
- **Save the whole list each time** (`SessionStore.save`). It cannot hold two continuations, rewrites everything on each commit, and had no way to read history back.
- **A position the Host remembers.** Simpler for a store, but it does not survive a restart by itself and nothing catches two writers.
- **A store passed to `Session.make` only.** An Agent, a Configuration and the CLI could not use one.
- **Let each store cope with whatever it is given.** A `Date` or a `Set` in a Tool's result would then read back differently from memory, from a JSON file and from a database, and a Provider already sends such a value to the Model as something else. An earlier rule denied a Tool Call whose parameters were not JSON only when it needed Approval ([ADR-0059](0059-let-the-host-answer-approvals.md)); checking every value once, where it enters, replaces it.
- **A check that never runs a value's code.** An earlier form of the rule refused getters and Proxies by looking at property descriptors, so that deciding ran nothing. It needed a hand-written walk in place of Effect's schema, and it guarded against code that is already trusted: Tools, Extensions and Providers run in the same process ([ADR-0067](0067-build-an-extension-from-a-record-or-an-effect.md)). Keeping a plain copy is what protects the conversation.

## Consequences

A Tool with a loose schema that returns a live object now fails loudly, naming the Tool, where the Model used to receive something else silently; a schema that encodes the value is the remedy, and the program still reads the live value from the Step. `@mitome/core` exports `isPlainData`, which is `Schema.is(Schema.Json)`, so that an adapter applies the same rule and adds none of its own.

A custom `program` no longer gets all-or-nothing staging: what a completed Step staged is committed even if the program fails later. A Step in flight when a Turn stops is still lost from the conversation, though its Tools may have run; recording that, and continuing a Turn after a crash, is durable execution and remains for issue #170, as do Compaction, Branch summaries and what Extensions may keep in the tree. eve and Pi Durable both record progress per Step (`docs/research/session-history-tree.md`), so that work adds to this shape and does not replace it.

Navigating the tree from the terminal needs commands, which are designed separately: the core ships none, and a Configuration binds the actions its Extensions contribute.
