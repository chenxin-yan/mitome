# Keep definitions as generic-preserving plain values

We revisited whether the authoring surface (`defineAgent`, `definePlugin`) should become class-based, fluent-builder, or Effect-idiom (`Agent.make`), and decided to keep plain-value `define*` factories — but make them generic-preserving so a Plugin's contributions survive the type system instead of being erased to `AnyPlugin`. The MVP tracks tool contributions (`name → { input, output }`) alongside the existing Resource type parameter; the Definition's Plugin tuple (already preserved via a `const` type parameter) carries them so the Session surface can later expose typed tool events without breaking changes. Typed hooks, typed Instructions, cross-Plugin type dependencies, and handler-completeness checking are deferred. Classes were rejected because the Host loads the user's definition module with the user's own copy of Core (ADR-0007/0023), making `instanceof` unreliable across package copies, and subclass-override extension contradicts the declarative Plugin model (ADR-0004); instance methods were rejected because they collapse the definition-as-data / runtime split the Host depends on. Fluent builders were rejected because chained type accumulation only pays when composition steps type-depend on one another, and Plugins deliberately do not (ADR-0004) — a preserved tuple plus one mapped type yields the same inference; the deepest-inference libraries in the ecosystem (TanStack, Drizzle, Zod) are value-factory based. A rename (`createAgent`, `Agent.make`) was rejected as buying no inference while burning migration cost: typed attribution, not spelling, is the differentiation. Guardrails: the contributions generic stays a flat record (no conditional-type towers) to protect declaration emit and tsserver performance, and detailed diagnostics remain in runtime validation while type constraints stay simple.
