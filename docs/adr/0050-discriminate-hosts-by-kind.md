# Keep Host kinds and capabilities explicit

Retain explicit Host composition, multiple declared Hosts, and the distinction between interactive execution and Channel capabilities. Interactive Hosts form an ordered terminal fallback chain ending in one-shot output; print/non-TTY bypass interactivity. Channels connect external surfaces including HTTP and later messaging, and may be request-driven, long-lived, or both. Host-specific options belong to that Host, not generic agent behavior; declaring a Host does not start it.

[ADR-0057](0057-use-effect-native-functions-and-optional-host-composition.md) replaces Promise `run`/`handle`/`serve` and Definition contracts with optional native composition, initially TUI and mountable HTTP. Exact signatures are pending; do not flatten different lifetimes into one universal run operation. [ADR-0056](0056-separate-history-compaction-and-execution-recovery.md) replaces response-body-owned execution with accepted work surviving observer disconnect.

Validate dynamically loaded compositions independently of static typing: known capabilities, required operations, unique Channel names, and actionable errors for uncalled factories. Reject unsafe mount names, including dot segments and malformed Unicode, when used in routing. Preserve explicit shared persistence ([ADR-0040](0040-compose-transcript-persistence-explicitly.md)), startup unwind, the explicit shutdown policy below, and isolated serving-Host failure reporting without an implicit restart loop. Authentication/ownership checks precede Route/history/model access.

Multiple TUIs may explicitly connect through the authenticated HTTP boundary to one running application and share its live Session. They are views/control clients, not independent execution owners; disconnecting either connected TUI detaches it without closing the application-owned Session. Retain an idle application-owned Session until an authorized explicit close or application shutdown, even after all clients disconnect. Automatic idle eviction is not the default; it would otherwise silently discard live Session state/resources or require reopening semantics. Admission/resource limits remain separate, and explicit close still coordinates active work rather than bypassing settlement. Stopping the owning application is separate. A standalone attempt to create a competing owner reports already owned rather than silently attaching or creating another writer. Automatic local-owner discovery/background startup on resume is not part of the initial attachment contract. Exact connection and shared-view control APIs remain to specify.

Standalone CLI shutdown stops admission and allows a configurable grace period for cooperative cancellation and cleanup, defaulting to **five seconds** to retain the current CLI default. The deadline is best-effort: if work remains when it expires and the event loop can respond, exit nonzero without claiming cleanup completed or uncertain writes rolled back. Hard wall-clock enforcement requires external supervision; a blocked event loop cannot enforce its own timer. An independent watchdog is not a required Mitome subsystem. Embedded library/Host code never terminates its containing process; the application owns escalation and must not release infrastructure still in use. Recovery after forced termination uses the last durable state, not an assumed successful shutdown.
