# Parse, Don't Validate at Boundaries

Core replaces the first-failure `validateAgentDefinition` with `compileAgentDefinition`, which parses an `AgentDefinition` into a `CompiledAgent` (providers map, merged tools/handlers/validators, joined instructions) in a single traversal that aggregates every structural and semantic problem into one `AgentDefinitionError` carrying a nonempty `issues` array with deterministic ordering; the session and tool-execution pipeline consume the compiled result instead of re-deriving it. Effect Schema decodes credential files, OAuth token responses, JWT claims, SSE events, the models.dev catalog and its cache, package.json version probes, and the CLI child-host IPC payload, with ParseErrors mapped to the pre-existing exact error messages rather than leaked defaults. Deliberate tolerances are preserved as spec: unknown SSE event and output-item types stay silently ignored for forward compatibility, non-conforming catalog models are filtered rather than fatal, and a corrupt catalog cache degrades to an ordinary miss (an accepted narrowing from per-entry filtering, since the refetch/stale fallback path is unchanged). Live object graphs — plugin construction in the SDK, provider factories, imported auth modules — keep typed imperative construction with plain `Error` throws instead of Schema decode, because they are not serialized unknowns; one planned migration was reverted on evidence: intra-plugin duplicate tool names must stay a synchronous `definePlugin` throw since `Toolkit.make` collapses duplicate names before core ever sees the plugin, while cross-plugin duplicates are aggregated by the compiler. Provenance violations (a provider lacking registration metadata) remain `Effect.die` — they are bugs, not user-reportable issues.
