# Persist committed history as versioned Transcripts

Sessions remain process-bound, scope-owned runtime objects. Their committed messages may be copied into a Transcript: a durable, ordered, Schema-backed value that may outlive its Session and seed a new Session. Resuming creates a fresh Session with freshly acquired Resources; it does not reattach to the old Session. Pending Approvals and every other part of an incomplete Turn remain ephemeral because Transcript updates use the existing turn-completion commit boundary. A Transcript has its own id and may name a parent Transcript id when it is forked.

`TranscriptSchema` is the single persistence contract for committed messages. Version 1 covers the message and content-part shapes in Effect AI 4.0.0-rc.108, including Tool calls and results, reasoning, approval parts, files, and message/part Provider options. Tool parameters and results must be JSON-compatible; unsupported live values fail at the serialization boundary instead of being changed or dropped. File strings, byte arrays, and URLs use distinct encodings so their Prompt representation round-trips without ambiguity. Unknown Transcript schema versions fail to decode.

Transcript migrations form an ordered chain with one step for each supported version transition. The chain is empty while version 1 is current. To change the format, add a migration from the previous encoded version to the next, increment `TranscriptSchemaVersion`, retain fixtures for every supported prior version, and test each sequential migration plus rejection of versions with no chain. Stores migrate after reading and persist only the current encoding; skipping a version or treating unknown versions as current is not allowed.

The event log is a separate, write-only observability record. Hosts append serializable, versioned Turn event DTOs as events occur, including a possibly truncated tail after process death. Events are never replayed to rebuild Session state; the Transcript is the sole resume source. This follows the traced production designs: pi persists finalized messages and resumes by projection, while Eve keeps a durable event stream for clients but resumes from versioned snapshots. Store APIs and event DTO implementation are separate follow-up work.

This amends ADR-0003's ephemeral-Session decision only by allowing Transcripts to outlive Sessions. It does not add event replay, mid-Turn recovery, Approval resurrection, or cross-process locking.
