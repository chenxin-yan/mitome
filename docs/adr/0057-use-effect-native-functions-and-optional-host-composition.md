# Use Effect-native functions and optional Host composition

Mitome's canonical agent authoring will be ordinary typed Effect-returning functions with an ambient, explicitly scoped Session, not a mandatory Agent Definition, Extension, per-agent service token, or Layer-valued agent. Native Layers provide infrastructure and native Tool/Toolkit/Schema/model types describe model work; service injection does not expose a Tool to the Model. This replaces the Promise-first facade and custom authoring machinery while retaining one shared execution implementation, independently usable primitives, replaceable loops, and arbitrary typed application results.

The app or Host owns one whole-function Turn, staging conversation across generations and committing once after successful completion and durable save when persistence is enabled. The Turn supplies a scope for resources and scoped child fibers acquired inside the invocation: cleanup and settling/cancellation of scoped children finish before commit. Programs explicitly join children whose success or results are needed. Use native Effect scoped-fiber semantics: stopping waits for an unjoined child but does not propagate its failure, including its own cleanup defect, into the parent. Such failures affect the Turn only when joined or explicitly propagated; defects in the Turn's own scope cleanup still prevent commit. A stronger all-child-failures supervision policy was rejected. Shared infrastructure is acquired outside the Turn. Returning a resource handle does not extend its lifetime. This chooses Turn-owned cleanup over allowing ordinary invocation resources to escape into the caller's scope. Reject overlapping Turns. Program or cleanup failure before commit does not publish partial conversation; a failed/interrupted acknowledgement after commit is not rollback, and uncertain store outcomes require reconciliation. Completed external effects are not undone. Execution returns a result Effect; bounded passive observation is separate from authoritative Approvals, cancellation, and outcomes. [ADR-0056](0056-separate-history-compaction-and-execution-recovery.md) remains the history/recovery contract: explicit durable operations, not arbitrary Effect replay or exactly-once external effects.

Keep `defineMitome` as optional declarative Host composition, not `new Mitome`, a required agent wrapper, or magic named-export discovery. User composition owns infrastructure, Provider/model configuration and persistence; one descriptor set supports discovery/auth without opening a Session or authenticated model client. Embedded use needs no Host imports. Deliver only the library and CLI/TUI, initially with TUI and mountable HTTP Hosts; Channels include HTTP and later messaging integrations. Discord/Telegram remain deferred. A process-local proof is internal only: the full #174 durability, History tree, Compaction, Skills, controls and subagent gates remain required.

## Configuration over convention

Skills and declarative subagent exposure are optional library composition, not a revived Extension framework or built-in Core discovery. Applications explicitly supply Skill locations, selection and exposure; neither Core nor the CLI/TUI silently scans home/project or client-specific directories. Supporting the selected `SKILL.md` format does not imply adopting filesystem search conventions. Keep reusable loading/catalog operations and native Tool/Toolkit adapters outside the execution kernel; use native Layers where infrastructure actually requires them. There is no generic plugin registry or lifecycle to implement first.

A main Agent may explicitly compose a declarative catalog referencing ordinary child Agent functions and the metadata needed at its exposure boundaries. Catalog declaration itself does not launch children, acquire their resources or expose every imported function to the Model. Direct typed delegation preserves application types; Model/wire/durable-result exposure needs the corresponding explicit Schema/codec or projection. Exact catalog/adapter signatures remain to qualify, not a mandatory Agent descriptor for every function.

Support both awaited and background delegation in the first replacement. Here “sync/async” means waiting for a child result versus receiving a handle to continuing work; it does not add synchronous-value or Promise-returning authoring facades. Execution initially remains in-process using native Effect lifetimes, with parent-linked children by default and separately application-owned jobs only when explicitly authorized. No built-in subprocess protocol or security sandbox is implied. In the coding Host, allow concurrent readers but one managed writer per workspace, including the parent; explicitly supplied independent worktrees permit parallel writers. Do not automatically create or merge worktrees. Trusted code outside managed operations can bypass those controls.

## Consequences and status

This is **accepted target policy, not implemented exports or verified signatures**. The [canonical library plan](../plans/effect-native-library.md) owns open contracts and proof gates; [#174](https://github.com/chenxin-yan/mitome/issues/174) owns delivery. Current code still implements Promise-facing definitions and Hosts, including the existing Effect facade. No production implementation is authorized by this record. Exact Session/Turn/generation/composition/Host contracts and export layout require proof before implementation.

This supersedes the authoring prescriptions in ADR-0001, ADR-0015, ADR-0022, ADR-0026, ADR-0032, ADR-0034, ADR-0043 and ADR-0045, and the Promise-first audience policy in ADR-0047. Fully obsolete records are removed under the prerelease cleanup policy; Git history preserves them, including already-superseded ADR-0035, ADR-0039 and ADR-0048, Extension identity ADR-0042, Hook ordering ADR-0049, and private Extension registry ADR-0053. ADR-0034 retains its package-consolidation boundary; ADR-0047 retains curated named exports; ADR-0054 retains partial-acquisition and reverse-cleanup guarantees. ADR-0041 rejects a custom DI graph, not native shared services/Layers.

Mixed decisions retain their useful trust, credential, CLI fallback, ordered Instructions, Tool validation/serialization, sanitized failure, lifecycle, explicit persistence and fail-closed Approval guarantees in the amended records. No historical Hook/Extension mechanism is mandatory merely because its behavioral guarantee survives. There is no backward-compatibility adapter requirement; obsolete prerelease guides/reference are removed rather than offered as a legacy API. New documentation must land with verified implementation, not speculative runnable examples.
