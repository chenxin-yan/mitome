# Infer Plugin Resources from the Layer in definePlugin

Core's `definePlugin` becomes the single resource-aware authoring path: `Resource` and `ResourceError` are inferred from the `resource` Layer value instead of explicit type parameters, and both the toolkitless and toolkit overloads enforce one rule — every service a Tool handler, Hook, or Tool result-decoding schema requires must be provided by that Layer, with the no-resource case degenerating to the existing service-free constraint. This turns the runtime missing-service defect into a compile error and removes the need to hand-write `Plugin<Resource>` objects (which erase typed handler params and Tool contributions) for resourceful Effect-native Plugins. Pre-release, backward compatibility was deliberately not a constraint; the unified rule was chosen over an additive third overload for signature economy. A `resources` array field was rejected: a Layer's output is already the composition point for multiple services (`Layer.mergeAll`), and the SDK's `setup` composes by returning a record, so a second plurality mechanism would duplicate what composition owns. ADR-0026's guardrails hold — flat generics, no conditional-type towers, detailed diagnostics stay in runtime validation. This amends ADR-0026 by un-deferring resource-coverage checking for handlers and Hooks.
