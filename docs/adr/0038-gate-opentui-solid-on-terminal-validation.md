# Gate OpenTUI and Solid on terminal validation

> Host composition now follows [ADR-0057](0057-use-effect-native-functions-and-optional-host-composition.md); the validated stack and terminal constraints below are retained historical evidence, not a new version selection.

The interactive Host specified by [#64](https://github.com/chenxin-yan/mitome/issues/64) will use OpenTUI core with its Solid reconciler only after the validation spike passes both automated and real-terminal checks. The coupled packages are pinned exactly to `@opentui/core@0.5.3` and `@opentui/solid@0.5.3`, with the reconciler's exact `solid-js@1.9.12` peer. The Solid preload and TUI package must resolve beside the selected Agent Definition and run inside the Bun Child Host with inherited stdio; Core and SDK remain Node-capable.

The spike (PR [#83](https://github.com/chenxin-yan/mitome/pull/83), kept out of the tree) recorded the evidence and result. Native loading, rendering, streaming, component behavior, terminal restoration, and clean exit pass automated checks; manual validation on the agreed MVP matrix (Ghostty on Linux) and the compiled Child Host smoke also passed, so the gate is **go** for the production shell in #73. The compiled smoke surfaced one constraint carried into #73: compiled Bun executables cannot resolve subpath exports parent-side, so preload resolution must be delegated to the spawned child. macOS rows extend the matrix later; a failure there would be a matrix regression, not a reopened stack decision.

The production TUI remains a thin rendering layer over a headless view-model. Explicit activation, print/non-TTY fallback and unsupported-terminal behavior follow [ADR-0019](0019-keep-the-cli-non-interactive.md). Approvals are fail-closed under [ADR-0051](0051-let-the-agent-author-decide-tool-approvals.md), not automatically approved. TUI and HTTP are initial target Hosts; this stack decision does not defer HTTP.
